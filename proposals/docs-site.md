# Documentation site & docs UX

Epic: turn `guide/` from markdown behind a redirect into a docs site that is professional,
pleasant to use, and a bit of fun — without giving up what the docs already do well (honest,
plain-language, example-led prose). From a docs deep dive on 2026-10-09; the quick fixes it found
(help links via the registry `guide` field, `find` in the README table, future-dated examples,
ADR links in user pages, `package.json` `homepage`) are done.

**Constraints any of this must keep** (CLAUDE.md): `/guide/<topic>` URLs are frozen into shipped
binaries, so `guide/*.md` keep their names and the site serves exactly those paths; `guide/` ships
in the npm tarball, so every page must stay readable as raw GitHub-flavoured markdown; the
help-vs-guide placement doctrine stands (terminal help is mid-task, the site is the sit-down
read).

## Ordered by payoff

- **A real site over `guide/` — VitePress, dev-dependency only** (ADR-0005's relaxed bar for
  dev deps). Why VitePress over Starlight: `cleanUrls` serves `/guide/exclude` from
  `guide/exclude.md` in place, so the frozen URLs need no redirect map and nothing moves; it
  renders GitHub's `> [!TIP]` alert syntax, which also renders on GitHub/npm, so the raw files
  stay first-class; local search is built in. Starlight wants content under its own
  `src/content/docs`. Avoid VitePress-only `:::` containers in `guide/` — they read as literal
  text in the tarball. Deploy to `s3cab.plantegral.com` (GitHub Pages or Cloudflare Pages) and
  check the domain keeps resolving (load-bearing for released binaries).
- **Examples that can't drift.** A doc-test script that runs each `console` block against a
  fixture `~/.s3cab` and a frozen clock and diffs the output against the page. The local
  commands (`snapshot`, `compare`, `list`, `tree`, `find`, `prop`) need no bucket; the cloud
  ones can run nightly against the integration bucket. Doubles as the fix for inconsistent
  example worlds (dates and paths still differ page to page — `restore.md` is 2026-06, the
  README 2025-11; Windows paths in some pages, POSIX in others).
- **Generated command reference.** One page per command from the `commands.mjs` registry +
  `command-details.mjs` — the same source as `--help`. The README's hand-kept command table
  (which drifted: `find` was missing) could be generated by the same script or shrunk to a link.
- **Slim the README** to pitch + install + quick start + links (~150 lines). Its "How it
  works", "Cloud repositories" and "Authentication" sections (~200 lines) restate
  `guide/format.md` and `guide/auth.md` — two homes for every format change.
- **A tutorial and a by-situation front door.** Today the only walkthrough is the README quick
  start and `guide/README.md` sends newcomers back to it. Landing entries by situation: *I
  deleted a file*, *I need last month's version*, *my laptop died*, *is my backup OK?*, *the
  bill is too high*. (`setup`, `list`, `status` have no `guide` link yet — the tutorial is
  their natural home.)
- **OS switcher** (Windows / macOS / Linux), remembered across pages — the paths are the most
  visible inconsistency. Needs a markdown construct that still reads acceptably raw.
- **Error index.** ADR-0030 messages are already constructive; give each a page anchor so
  pasting an error into search lands on its fix.
- **Exclude-pattern playground.** `src/lib/exclude.mjs` imports only `node:path` and
  `path-match.mjs`, so the real matcher can be bundled for the browser — paste paths, type
  patterns, see what's dropped and by which pattern. Same code as the CLI, so it cannot disagree
  with it. A `find` pattern twin is the same idea.
- **Annotated snapshot anatomy** — hover a column of a real snapshot line for its meaning.

## Fun, with a point

- **"The day s3cab disappeared"** — a recover-by-hand challenge: a bucket listing and a
  snapshot, get `beach.jpg` back with `gunzip` and `curl`/`aws`. The no-lock-in promise as a
  game; the clean-room restorers ([ADR-0096](../docs/adr/0096-three-implementations-prove-the-format.md))
  are the "show me" answer.
- **One running story** — `photos`, `my-backups`, `beach.jpg`, the 2019 hike already recur;
  make it one cast and one timeline, generated by the doc tests above.
- **Generated terminal recordings** (VHS/asciinema) from the doc-test fixture for the home
  page, so they never go stale.
- **Keep the existing voice** ("the cardinal sin", "fat-finger backstop") — wit in headings,
  asides and the 404 page, never in commands or warnings.
