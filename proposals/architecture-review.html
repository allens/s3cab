After — plan, then execute

▼ plan crosses the seam as data

PUT loop · recordObjects-before-snapshot ordering · snapshot-last invariant

Problem. uploadSnapshot interleaves the upload-set decision (candidates − cache, first-path-wins) with the PUT loop, so only uploadCandidates is unit-tested; the rest of the decision runs only against real S3. The backup command has no test at all.

Solution. Extract the decision into a pure planUpload; uploadSnapshot shrinks to executing the plan — exactly how restore already splits planRestore (pure, tested without S3) from its I/O loop.

  • Interface is the test surface: Maps in, plan out
  • Locality: upload-set rules concentrate in one module
  • Leverage: mirrors the accepted planRestore shape
  • Unblocks a backup command test
  • No ADR tension — purely additive

3 · One snapshot-name authority — and close the two-clock gap

Worth exploring carried latent bug

src/commands/snapshot.mjs:37,57,134–137 · src/lib/snapshot-file.mjs:263–269 · src/lib/compare.mjs:21

Before — the format leaks into three modules, off two clocks

sequenceDiagram
  participant S as snapshot.mjs
  participant C as clock
  participant F as snapshot-file.mjs
  S->>C: now() #35;1 → filename "…T0915"
  Note over S: await readSnapshot(previous)
(clock keeps ticking)
  S->>C: now() #35;2 → header "…T09:16" ⚠
  S->>F: writeSnapshot(name, datetime)
  Note over F: snapshotNames regex
re-encodes the filename shape
  Note over S,F: compare.mjs normalizeName strips
".tsv(.zst)" a caller shouldn't know

After — one capture, one recognizer

snapshot-name authority (beside parseSnapshotStream)

one now() → { name, datetime } · the recognizer regex · the extension-normalizer

→ snapshot.mjs consumes { name, datetime } — consistent by construction

→ compare.mjs drops normalizeName

→ format changes are one-place edits

Problem. The minute-precision name format is spelled in three modules, and snapshot.mjs reads the clock twice with an await in between (line 37 vs 57) — cross a minute boundary and the filename disagrees with its own #SNAPSHOT header.

Solution. One capture returning { name, datetime } plus the recognizer, living in snapshot-file.mjs beside the parser. normalizeName's extension-stripping (a grammar detail leaking across the seam into compare.mjs) folds in.

  • Closes a real (if rare) skew, not just a style itch
  • Locality: generation and recognition side by side
  • Seam stops leaking .tsv.zst into callers

4 · Thread the previous snapshot through snapshot → compare

Worth exploring new hot path

src/commands/snapshot.mjs:42–47, 80–84 · src/lib/compare.mjs:66–101

Before — the previous snapshot is parsed twice per run

sequenceDiagram
  participant S as snapshot.mjs
  participant F as snapshot files
  participant C as compareSnapshots
  S->>F: readSnapshot(previous) — parse #35;1
  Note over S: entries → hash lookup for the walk
  S->>F: writeSnapshot(new)
  S->>C: compare(since: previous, until: new)
  C->>F: readSnapshot(previous) — parse #35;2 ⚠
  C->>F: readSnapshot(new) — parse #35;3

Same file, fully re-parsed — zstd decompress + line parse of every entry, twice, on the snapshot hot path.

After — data already held crosses the seam once

sequenceDiagram
  participant S as snapshot.mjs
  participant F as snapshot files
  participant C as compare
  S->>F: readSnapshot(previous) — parse #35;1
  S->>F: writeSnapshot(new)
  S->>C: compare(sinceSnapshot: held, until: new)
  C->>F: readSnapshot(new) — parse #35;2

Re-reading the new snapshot stays — that round-trip is a free verification of what was just written.

Problem. snapshot reads the previous snapshot for its hash lookup, then compareSnapshots re-reads the same file as the diff baseline. On a large set that's a full decompress-and-parse done twice — the exact per-file-overhead pattern the repo's hot-path convention warns about, and its prescribed fix is this one: thread the data you already have through the interface, never cache it module-level.

Solution. Let the compare seam accept an already-parsed since side (e.g. entries alongside the name), or have snapshot compose the pure diff with what it already holds. The trade-off to grill: the first widens compareSnapshots' interface; the second moves display assembly.

  • Saving lives in the interface, where the type checker sees it rot
  • Hot-path cost is per-entry × thousands of files
  • Pairs naturally with candidate 5 (both reshape the compare seam)

5 · Test diff at its own interface, not through the I/O shell

Worth exploring carried · 2026-06-23 §2 test discipline, not structure

Before — deepest logic, most expensive test access

tests build .tsv.zst fixtures (withSnapshotFile + stringifySnapshot)
▼ file I/O + zstd
compareSnapshots — resolve names, read files, format display
▼ only path to…

After — test the pure core at its own seam

Problem. Every test of the move-pairing logic pays for compressed fixture files and the resolution shell around it; edge cases are costly to set up, so fewer get written.

Solution. Drive the already-exported, pure diff directly. No structural change — an internal seam consciously used by its own tests.

  • Interface is the test surface
  • Tests survive I/O and format refactors
  • Cheapest candidate on the list

Not re-suggested — standing rejections from prior passes

Recorded in architecture-improvements.md (rejected & parked section); re-checked, still hold. A future pass should skip these too.

  • Split a snapshot codec/grammar module out of snapshot-file.mjs — rejected twice; contradicts ADR-0028 (the writer owns the grammar, markers already live in one place).
  • Narrow the snapshot read surface (collapse readSnapshot/readSnapshotFile/parseSnapshotStream/snapshotNames) — each export has a distinct real caller; the reader half is genuinely deep.
  • Unify “resolved set” (set + env) into one value / a SetContext — parked; contradicts ADR-0022's deliberate two-door split. Friction is real but not worth reopening the ADR.
  • Concentrate the list-and-strip mechanic across objects/remote/set-marker — shared part is ~2 lines; the per-prefix modules are the design (ADR-0013/0023).
  • Restructure the remote engine or config layer — found already deep and cleanly seamed by both prior reviews; this pass agrees.
