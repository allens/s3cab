Problem. A classifier in another module matches name === "AssertionError" or two zlib codes, so every assertion on a read path counts as snapshot damage: run against the real modules, readSnapshot("", "x") and an S3 reply with no body both classify as damaged, where the doc promises "Unknown → not corruption → abort".

Solution. The reader turns every codec and validity failure into its own damage error, and the three callers catch that type; the classifier names no codec and no Node class.

  • locality: "damaged" decided where it is known
  • error.mjs's own rule: caught by type → a subclass
  • an outage can't read as data loss
  • one test through the reader replaces hand-built errors

Knowledge moves into snapshot-file.mjs, so ADR-0028 and the codec-split rejection stand. ADR-0074 put the classifier in referenced.mjs for its zero imports; a type the reader exports changes who imports whom, so read it first.

A download's body is outside the retry

Worth exploring mock (a loopback server) a live defect

src/lib/s3.mjs — requestErrorRelay :504–568, getStream :620–628 · consumers src/lib/objects.mjs:93 (getObject), src/lib/remote.mjs:194 (readRemoteSnapshot), :436 (downloadRemoteSnapshots) · src/lib/restore.mjs:578–588

Before — the relay ends at the headers

sequenceDiagram
  participant C as a consumer
  participant R as the relay
  participant S as S3
  C->>R: getStream
  R->>S: GET
  S-->>R: headers
  R-->>C: the body, unread
  Note over R: the retry window ends here
  S--xC: the connection drops mid-body
  Note over C: ECONNRESET "aborted", the restore stops

After — s3.mjs owns the GET to its last byte

sequenceDiagram
  participant C as a consumer
  participant M as s3.mjs
  participant S as S3
  C->>M: the object, please
  M->>S: GET
  S--xM: the connection drops mid-body
  Note over M: rides it out, as a request does
  M->>S: GET, the rest
  S-->>M: bytes
  M-->>C: the whole body, or networkError

Problem. The relay wraps a call that returns when the headers arrive, and three consumers drain the body afterwards, so a connection that drops mid-body gets no retry: run against a loopback server that cut the socket after 1,000 of 1,000,000 bytes, getObject threw a raw ECONNRESET: aborted after one GET and 121 ms.

Solution. s3.mjs owns the whole GET, body included, with the guarantee a request already has.

  • leverage: three consumers, one guarantee
  • the read side gets putFile's depth
  • a multi-GB restore survives a blip

Touches ADR-0068, ADR-0065 and ADR-0091, all written about uploads and requests. The model tier can't see this: its fake replaces getStream.
