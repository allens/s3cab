One stderr-progress module — three adapters, one live gating bug

Strong in-process

src/commands/snapshot.mjs:91–132 · src/lib/s3.mjs:309–323, 416–429 · src/commands/restore.mjs:124–160 · src/lib/style.mjs

Problem: the in-place-stderr mechanic — gate on TTY, write \r, track whether a line was drawn, close with \n, fall back to plain lines off a TTY — is implemented three times, and the copies disagree: snapshot's counter writes \r unconditionally, so a redirected or CI run gets carriage-return spam. PR #147's style.mjs centralised the gate but not the mechanic; its header's "every consumer routes through here" promise is already violated.

Solution: a lib/progress.mjs module owns the mechanic behind one small interface; the three renderers (byte bar, done/total counter, percent+elapsed) stay as injected pure functions. formatUploadProgress, already pure and tested, becomes one of them.

The objects cache needs its third verb: atomic rewrite

Strong slice-5 prep

src/lib/objects.mjs:143–189 · docs/adr/0042 · docs/design/backup.md (verify + cleanup)

Problem: the per-bucket objects cache exposes read-all (knownObjects) and append (recordObjects, a bare appendFileSync). ADR-0042 requires verify to rewrite the cache from a completed LIST (atomic temp + rename, never from a partial LIST), and cleanup --delete must rewrite it from stored − deleted. Without a lib verb, both commands would grow the write-and-rename dance inline — commands doing lib-work, twice, past the seam that owns the file's path and format.

Solution: add rewriteObjects(bucket, hashes) to objects.mjs — temp file + rename, the atomic pattern its own getObject already uses. The cache becomes one deep concept: three verbs, one owner, one path literal, one atomicity guarantee, next to the staleness-asymmetry comment that already explains it.

The store's listing drops Size — verify's size cross-check needs it

Worth exploring slice-5 prep

src/lib/objects.mjs:122–130 · docs/design/backup.md (finding class 2)

Problem: listObjectHashes collapses each listed object to a bare hash. Verify's size-mismatch check needs hash → size from the same LIST it already pays for (the design forbids extra requests). As shaped, verify would have to bypass objects.mjs and call s3.mjs's listObjects directly — leaking the objects/ prefix literal out of the one module that owns it.

Solution: a size-carrying enumerator listStoredObjects(bucket) → AsyncGenerator<{ hash, size }>; listObjectHashes becomes a thin map over it. The interface grows one small entry; the seam stays sealed.

  • Size-mismatch detection testable at the lib seam

Lift seedStarterExclude's guard to sets.mjs

Worth exploring small

src/commands/setup.mjs:179–188 · src/lib/sets.mjs:76–126

Problem: PR #146's split is mostly right — starter data + read/write primitives in sets.mjs, policy in setup.mjs. But the load-bearing guard ("never clobber an existing exclude file") is a private command function reachable only through the async S3 create flow, so its contract is only testable end-to-end.

Solution: move the idempotent seed into sets.mjs as seedStarterExclude(name) → boolean (wrote / already had one); setup keeps only the user-facing notice. The module's exclude surface then reads as one concept beside the data it guards.

After

  • Locality: guard beside the data + primitives
  • Small — testability gain, not a depth lever

One snapshot-name authority — close the two-clock gap

Worth exploring · latent bug

The timestamp format is spelled in three places: snapshot.mjs renders "now" twice from two separate clock reads with an await between (filename line 37 via getTimestamp; #SNAPSHOT header line 57) — a minute-boundary crossing makes the filename disagree with its own header — plus the snapshotNames regex (snapshot-file.mjs:263–266) and normalizeName's extension-strip (compare.mjs:21). One authority in snapshot-file.mjs: single now() → { name, datetime }, plus recognizer and normalizer.
