Bugs found en route

A # comment in dirs.txt is walked as a directory

readSet and readSetConfig keep # lines; the next walk aborts with “These directories … aren't available: # old drive”. parseLines even documents itself as the rule both files are read by — a unification that never happened. Candidate B carries the fix.

aws --save --profile <p> silently drops the profile

stack-arns.mjs builds its CloudFormation client with { region } only, so the DescribeStacks read runs on ambient credentials — the admin profile the user just deployed with is accepted and ignored. Honor it (v3 clients take a profile option) or reject the combination.

A — backup re-derives what snapshot() already returned

Strong in-process

src/commands/backup.mjs:47–57 · src/lib/compare.mjs (the CompareResult contract)

Before — three reads of one fact

flowchart TB
  S["snapshot(set)"] -->|"CompareResult (until, since) — discarded"| B["backup"]
  B -->|"listSnapshotNames latest"| D[("snapshots dir")]
  B -->|"listSnapshotNames().find(n < name)"| D
  B -->|"guard: 'No snapshot was produced'"| B
  classDef leak stroke:#dc2626,stroke-width:2px;
  class D leak

After — the interface already carries it

flowchart TB
  S["snapshot(set)"] -->|"{ until, since } destructured"| B["backup → upload(until, since)"]
  classDef deep fill:#064e3b,stroke:#059669,stroke-width:3px;
  class S,B deep

Problem. After await snapshot(…), backup reads the fresh name back off disk and re-derives the baseline with a second directory read — but the CompareResult it just discarded carries both: until is the fresh name, since is the previous latest. The in-code comment claiming “snapshot() returns its diff, not the name” is false.

Solution. const { until, since } = await snapshot(…) — delete both reads, the guard, and the stale comment (~10 lines).

  • Locality: backup↔snapshot agree by construction
  • Two directory reads and one guard deleted
  • Interface unchanged; tests feed CompareResults
Grill first: the S3CAB_DEBUG same-minute-overwrite edge (diff's since can equal until) — debug-only; both forms already die on the immutable-snapshot PUT.

C — drop objectExists's metadata heuristic

Worth exploring

src/lib/s3.mjs:476–489 (the multipart no-clobber preflight)

Before — a branch that can only waste bytes

sequenceDiagram
  participant P as putFile
  participant S3
  P->>S3: HEAD (200, no custom metadata)
  Note over P: treated as "absent"
  P->>S3: multipart upload — full body sent
  S3-->>P: PreconditionFailed (IfNoneMatch)
  Note over P: return false — same answer, N MB later

After — any 200 HEAD is present

sequenceDiagram
  participant P as putFile
  participant S3
  P->>S3: HEAD (200)
  Note over P: return false — skip upload
  Note over P,S3: conditional PUT stays the real guard

Problem. The “exists but has no metadata → treat as absent” branch reaches the identical outcome the conditional PUT would give — after uploading the whole multipart body first.

Solution. Any successful HEAD counts as present; delete the metadata inspection.

  • One branch fewer, same guarantees
  • No wasted body upload on metadata-less objects

Problem. Overlapping member dirs are only reported after the entire walk — a wasted multi-minute pass on a big set — via a second full loop.

Solution. Move the seen check into the collect loop. Rejected alternative: a pre-walk root-containment check — exclude patterns can make nested roots a working config today, so only the file-level check is faithful.
