Problem: a full zstd decompress + per-entry parse done twice per run — the per-file-overhead pattern the hot-path convention warns about. (The new snapshot's re-read stays: it doubles as round-trip verification.)

Solution: thread the data through the interface (never a hidden cache). Two shapes to grill: the compare seam accepts an already-parsed since side, or snapshot composes the pure diff directly. Pairs naturally with card 5 — both reshape the compare seam.

  • Halves the previous-side parse cost on large sets
  • Saving lives in the interface, visible to the type checker
