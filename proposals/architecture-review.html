A · Deepen progress.mjs to own a counted pass

Strong in-process

Surfaced independently by two of the three sweeps.

Before — the recipe, twice

walk.mjs

label = "…'<dir>'…"
createProgress(stderr)
paint bare label
due() gate ⟵ no clock
label + count + elapsed

After — one deep module

walk.mjs
label + count
upload.mjs
label + count

progress.mjs

countedPass(stream, label, () => n)

TTY gate
redraw cadence
the clock tick
bare-label paint
count + elapsed
retained tally

The interface is the test surface: a passed-in clock makes the whole pass assertable off a terminal.

Problem

progress.mjs owns the terminal mechanic and the cadence, but the shape of a counting pass — bare label, then <label> <count> in <elapsed>, then a tally that must survive off a terminal — is re-typed identically in two modules, and the clock that drives the tick is hand-rolled twice and missing from the third.

Solution

Give progress.mjs the concept it lacks: a counted pass it draws on its own clock and closes with a retained line — so no caller reaches for isInteractive or setInterval, and the walk cannot be the one pass that forgets.

The live consequence

The walk redraws inside for (const path of walkFiles(…)) — data-driven, not clock-driven. walkFiles blocks on readdirSync per directory and on resolveFileType's lstatSync fallback (the NFS/FUSE case), and yields nothing while descending a subtree it keeps no files from. In each, the count and its elapsed clock freeze — the exact fault ADR-0076 §3 was written about, on the one pass that never got the fix, and the pass that runs longest on the biggest sets.

Wins

  • locality: one pass shape, one place
  • the walk's line stops freezing
  • isInteractive stops leaking to three callers
  • four copies of one template collapse
  • leverage: injected clock ⇒ testable off a TTY
  • progress.mjs's own doc claim becomes true again
Extends ADR-0076, doesn't reopen it — 0076 already rules that bursty or blocking passes must be clock-driven. This is cashing that rule at the site that missed it, and moving the tick inside the module that already owns cadence.

Test-surface note

Nothing anywhere asserts on Finding files in or Scanning existing objects. The progress.mjs core mechanic itself is well covered (progress.test.mjs, including flicker ordering) — the gap is everything the callers built on top of it.

Problem

resolveCredentials returns from the RA branch before entering its try, so only the absent identity case is wrapped. Every runtime CreateSession failure — expired certificate, 403 from STS, socket error, timeout — reaches the user as a raw HTTP dump. The request-time relay can't catch it either: createSession issues a raw node:http request, so it never passes s3.mjs.

Solution

Bring the createSession call inside the same failure handling the standard chain already gets, so an RA runtime failure is classified by the existing predicates and lands in the RA credentialCase — or, when the message says so, the expiry one.

The asymmetry's cost

The once-per-machine setup failure gets the polished five-line fix. The recurring one — a client certificate that aged out — gets an HTTP status and a response body. isExpiredSignIn matches /\bexpired\b/i and would very likely fire on that body, but is never consulted on this path.

Wins

  • one credential-failure vocabulary, four modes
  • an aged-out certificate says how to fix it
  • locality: ADR-0037's remedy table finally total
  • gives resolveCredentials its first test
Completes ADR-0075/0037 rather than contradicting them — 0075 extended expiry diagnosis to resolve time for the standard chain; the RA adapter, added by ADR-0057, was never brought into it.

Problem

Three of generateSnapshot's six options are readBaseline's own fields renamed and re-threaded by hand — identically at 2 of 2 call sites. The interface is wider than what it hides, and the widening is pure re-spelling.

Solution

Wins

  • interface shrinks 6 options → 4
  • the dead branch becomes unwritable
  • locality: baseline invariant in the type
  • two porcelain commands lose a third of their body
Does not reopen ADR-0069. The through seam — one optional parameter carrying the whole snapshot-vs-backup difference — was examined again this pass and found clean. This is about the three baseline options beside it, both of which (sizes, previousInstant) post-date the last architecture pass.

Problem

The module normalizes the pattern side, then documents in prose a calling convention the caller must honour on the subject side. The directory rule — trailing / — is implemented in walk.mjs, so it is reachable only through the filesystem.

Solution

Move the subject-side normalization and the directory marking inside exclude.mjs, so its interface answers "does this entry match, and by which pattern" instead of handing back a RegExp with rules attached.

The least-tested half is the most-used half

Four of the six active starter patterns are directory form — **/node_modules/, **/.git/, $RECYCLE.BIN/, System Volume Information/ — and exclude.test.mjs has no directory-exclusion case at all; its helper (compileExclude(pattern).test(path)) re-implements the convention and cannot express the rule. The only coverage is one walk.test.mjs case that builds a real temp tree.

Wins

  • the directory rule becomes unit-testable
  • three unwritten obligations disappear
  • locality: one home for "does this match"
  • the walk stops knowing the grammar

F · The snapshot pass's counters are unobservable

Strong in-process
src/lib/snapshot.mjs:157-158, :166-170, :184-199, :252-297, :314-362

Off a TTY createProgress writes nothing, so every counter is inert under node --test.

After — the counters cross the interface

tests
progressLine
tests
the pass
counters asserted where computed

Injecting the sink and the clock makes the denominators assertable without a terminal.

Problem

progressLine was extracted for testability and got 16 tests — but every real defect in this pass lives in what is passed to it, and none of that is reachable through the current interface. snapshot.test.mjs imports exactly one symbol; backup.test.mjs mocks the other two away.

Solution

Make the pass's counters inspectable at generateSnapshot's own interface — or let withProgress accept the sink and the clock — so the denominators are asserted where they are computed rather than where they are formatted.

The behavioural question this hides

bytesDone += props.size counts a reused file's bytes, and fileProps returns the stored props without reading a byte. So "38% of 2.4 GB" means bytes read on a first run and files settled on a no-change run — a difference no progressLine test can see. Whether that is right is a product question; that nothing can observe it is the architectural one.

Wins

  • the interface becomes the test surface
  • deleting sizes: stops being silent (see C)
  • the byte denominator gets a stated meaning
  • locality: pass behaviour verified in one place

H · "Deliberate ≠ fault" is decided twice

Worth exploring in-process
src/lib/verify.mjs:26-39, :59-71, :138-149
src/commands/restore.mjs:148-173, :195-215, :227-234

verify — pure, eager

stored.get(hash) === undefined
deleted.get(hash) ?
→ expectedMissing (exit 0)
→ problems (exit 1)

restore — imperative, lazy

isObjectNotFound(error)
recordFor(hash) ?
→ deleted[] (exit 0)
→ missing[] (exit 1)
same question · same Map<hash, RecordedDeletion> · same exit-code rule · no shared name

Problem

One domain rule — an absent object is either a recorded deletion (context, exit 0) or an unexplained absence (a fault, exit 1) — is implemented in two modules with no shared name, and its rationale is spelled out in prose in both. A change to what counts as "explained" has two homes.

Solution

Name the classification once, in the deletion-record vocabulary, and let both callers keep their own I/O policy — eager for verify's whole-bucket scan, lazy for restore's first casualty.

Abuts a standing rejection — do not conflate

The tenth pass declined "the three shapes of the deletion-record lookup" because verifySet, planCleanup and baselineHashes ask distinct questions (map / membership / keys). That reasoning holds. This is a different claim: restore is a fourth consumer that asks the identical question to verifySet, in the identical shape, and reaches the identical exit-code rule. Two consumers of one question, not three of three.

Wins

  • locality: one definition of "explained"
  • ADR-0064's exit-code stance stated once
  • restore's classifier becomes pure and testable

Problem

formatCount exists because "six digits run together are unreadable at a glance", but whether to apply it is re-decided at every interpolation — so the compare and verify renderers get it wrong for precisely the figures that reach six digits.

Solution

Settle the rule once — any count that can pass 999 is grouped — and apply it at the eight sites. The leverage is already in format.mjs; nothing new is needed at the interface.

Top recommendation

A · Deepen progress.mjs to own a counted pass

Two of the three sweeps found it independently, from different directions. It is the only candidate where the missing piece of an interface produces a live behaviour fault: the walk's line freezes on readdirSync, on the lstat fallback, and while descending a subtree it keeps nothing from — the fault ADR-0076 §3 already ruled against, on the longest pass over the biggest sets. Everything it touches is in-process, so an injected clock makes the whole pass assertable off a terminal, where today nothing asserts on those lines at all. It also repairs a doc claim that has quietly gone false.

Runner-up: B · Roles Anywhere escapes the credential-error family — narrower, but it is the recurring failure (a certificate that aged out) that currently prints an HTTP body where every sibling failure prints the fix.
