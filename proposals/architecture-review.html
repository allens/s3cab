Problem. “Which provider knobs does this set’s env file carry” is re-implemented by each caller, and the copies have already drifted: providerOverrides predates Roles Anywhere, so a keyless RA set renders no provider block in list <set> — documented to mean “relies on the ambient AWS setup” — while provider <set> correctly says “Roles Anywhere (keyless)”. A live bug (→ bugs.md).

Solution. A pure readProviderConfig(values) → ProviderConfig ({ profile, endpoint, region, keyId, rolesAnywhere }) in lib/provider.mjs beside its write twin; both commands consume it, and providerOverrideLines gains its RA line. Grilled decisions: raw keyId at the seam; type named ProviderConfig, owned by lib/provider.mjs; sign-in: Roles Anywhere (keyless) first in list’s block; list’s keys line matches provider (set (…F7Q2) via keyTail).

  • locality: knob mapping lives once
  • fixes the RA list bug by construction
  • leverage: next knob = one edit
  • read twin mirrors the accepted write seam
Not the rejected credentialMode() classifier (2026-07-14): no mode enum — both callers already read the same five values from the same file; this names that one mapping. ADR-0055’s “auth is a bag of AWS_*” is untouched.

Prefix and extension each owned by their module; six literals become compositions.

Problem. snapshot-file.mjs centralizes the recognition/strip direction and its doc claims the naming convention lives in one place — but the construct direction is six hand-spelled `${name}.tsv.zst` literals across two modules: the grammar leaks across the seam, and a codec change is a six-site hunt.

Solution. Export snapshotFileName(name) from the owner; the six sites compose it with their own piece (S3 prefix, local dir).

  • the “one place” claim becomes true
  • locality: codec change = one edit
  • the de-leak compare.mjs already got (PR #168)
Aligns with ADR-0028 (naming pulled into the writer) — the opposite direction to the rejected codec split.
